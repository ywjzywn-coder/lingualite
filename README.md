# 轻译 LinguaLite

一个轻量的语言学习浏览器扩展：**视频双语字幕 + 网页沉浸式翻译 + 划词查词 + 生词本 + 无字幕视频语音转录**。

设计目标是"够用且不臃肿"：没有账号、没有服务端、没有埋点，所有数据只存在本机。对比同类产品（Trancy 安装包 5.9 MB、每个页面注入约 6.7 MB JS），本项目的脚本合计约 110 KB。

## 怎么用

| 入口 | 操作 |
| --- | --- |
| 右键菜单 | 页面空白处右键 → 一个会切换的条目：未翻译时是「翻译此页（双语对照）」，翻译后变成「还原原文」；选中文字时另有「翻译选中文本」「朗读选中文本」 |
| 工具栏图标 | 点击打开弹窗：同一个按钮按状态切换「翻译此页」/「还原原文」，外加翻译所选文本、朗读、以及所有设置 |

网页翻译做成**一个可切换的条目**，而不是「翻译」和「还原」两项。难点在于右键菜单是全局的、不是每个标签页一套，所以由 Service Worker 记录各标签页的翻译状态，菜单标题跟随当前活动标签页改写（切标签页、切窗口、页面导航、状态上报时都会重算）。

### 网页沉浸式翻译

点「翻译此页」后，译文会以浅色文本插在每一段原文的下方，页面右下角出现进度胶囊：

- **只翻可视区**：先翻当前屏幕附近的内容（预取范围 1.2 屏），向下滚动会继续翻译，不必等整页跑完。
- **智能跳过**：代码块、SVG 图标文字、输入框、`contenteditable` 区域、`notranslate` 标记都不会被翻译。
  至于「这段是不是已经是目标语言」，**只在整页就是目标语言时才逐段判断**。逐段判断对中日文并不可靠——两边共用汉字，纯汉字的日语（如「東京大学 大学院情報理工学系研究科」）很容易被判成中文，一旦跳过就是整段没有译文，而漏翻比多翻一次代价大得多。判断整页语言用的是标题加开头若干段，样本够长才可靠；非目标语言的页面一律全翻，本来就无需翻译的片段由「译文与原文相同则丢弃」兜底，因此不会出现重复行。
  另外两条硬规则：**含假名的一律不算中文**；目标是简体时判定为繁体的段落不跳过，交给翻译完成繁简转换。
- **复制保护**：在双语文档里选中文字复制时，剪贴板只保留原文，不会把译文一起带走。
- **随时还原**：右键「还原原文」、弹窗的「还原」按钮、或进度胶囊上的「还原」，都会彻底移除译文、标记与注入的样式。
- **SPA 支持**：换页或无限滚动加载的新内容会被自动识别并翻译。
- **失败可重试**：某批请求失败时，失败段落会显示原因，胶囊上出现「重试」按钮。

> 目前没有绑定任何键盘快捷键。快捷键会被扩展独占，等功能稳定后再按需添加。

## 界面体系

视觉规范取自 [shadcn/ui](https://ui.shadcn.com/) 的 neutral 主题。项目用 Preact 而非 React，也没有引入 Tailwind，所以做法是**把它的设计令牌与组件配方改写成等价 CSS**，而不是装它的组件库。

样式分三层，边界按「谁用得到」划：

| 文件 | 内容 | 加载方式 |
| --- | --- | --- |
| `src/ui/tokens.css` | 设计令牌（oklch 色彩、圆角梯度） | 扩展页面 link；内容脚本内联 |
| `src/ui/controls.css` | 按钮、分隔线等两边都用得到的控件 | 扩展页面 link；内容脚本内联 |
| `src/ui/components.css` | 卡片、表单、开关、状态提示等页面专用组件 | 只有扩展页面 link |

这样内嵌进网页的 UI 不必带上用不到的组件样式。当前 `content.js` 约 37 KB（其中约 7 KB 是内联的令牌与控件）。

深浅色的处理有个容易踩的坑：`tokens.css` 里浅色和深色**各写了两处**，一处给 `:root`（扩展页面跟随系统偏好），一处给 `[data-theme]`（Shadow DOM 里 `:root` 不匹配，只能靠属性）。两处数值必须一致，`tests/tokens.test.ts` 会解析文件逐条比对。另外显式属性块必须排在系统深色媒体查询**之后**，否则在深色系统上无法强制指定浅色。

网页里注入的 UI（划词气泡、进度胶囊）用 Shadow DOM 隔离，配色跟随**页面背景**而不是系统偏好；扩展页面用 `applyTheme()` 在 `<html>` 上设 `data-theme`，与内嵌 UI 共用同一套组件写法。


### 加载到浏览器

1. 打开 `chrome://extensions/`
2. 右上角打开 **开发者模式**
3. 点击 **加载已解压的扩展程序**，选择本项目的 `dist` 目录
4. 首次安装会自动打开设置页；之后可点工具栏图标打开弹窗

### 自测步骤

1. **默认配置直接可用**：设置页 → 「试译」→ 点「翻译成 zh-CN」，应当几百毫秒内返回中文译文，元信息显示 `引擎 Google 免费接口`。
2. **缓存生效**：再点一次，`命中缓存` 应为 3 段、`请求 0 次`。
3. **接入自己的模型**：设置页 → 翻译引擎选「AI 模型」→ 选一个预设（如 DeepSeek）→ 填 API Key 与模型名 → 回到「试译」再翻一次，元信息应显示你配置的服务商名。
4. **思考强度**：把思考强度设为「不用思考」，翻译速度应明显快于「高」。
5. **失败降级**：故意把 API Key 改错，再次试译；若「模型失败时自动降级」是开启的，应当仍能返回译文，且引擎名带「降级到 Google」。
6. **弹窗**：点工具栏图标，切换目标语言与功能开关，刷新设置页应看到设置已同步。
7. **划词翻译**：在任意网页选中一段文字 → 右键「翻译选中文本」，气泡应出现在选区下方；弹窗顶部的按钮结果一致。
8. **划词朗读**：选中文字后右键「朗读选中文本」，应听到浏览器内置语音。
9. **网页翻译**：在英文文章页右键 →「翻译此页（双语对照）」。译文应逐段出现在原文下方，右下角显示 `翻译中 n/N`；向下滚动继续翻译；代码块与已经是中文的段落不应被翻译。
10. **菜单会切换**：翻译完成后再右键，同一位置的条目应变成「还原原文」；点它还原后，再右键又变回「翻译此页」。切换到别的标签页时标题也会跟着那个页面的状态变。
10. **复制保护**：在翻译后的页面上选中一整段复制，粘贴出来应当只有原文、没有译文。
11. **还原**：右键「还原原文」，译文、右下角胶囊、注入的样式都应消失，页面与翻译前一致；再次翻译应能正常工作。
12. **受限页面**：在 `chrome://extensions` 这类页面触发操作，工具栏图标应闪出 `!` 角标并提示原因，而不是毫无反应。

## 翻译提示词

翻译质量几乎完全由提示词决定，所以它是可配置的，而不是写死在代码里。

**固定规则**（`src/engines/prompt.ts`，约 400 token）负责四件事，用户改不到：

- **输出格式**：必须保持 `<<1>>` 编号与 `%%` 分隔符、顺序与段数一致；禁止合并拆分、禁止加标题注释、禁止套代码围栏——这几条直接决定批量解析会不会失败。
- **质量**：译意不译词、像母语者那样写、不添油加醋也不省略、保持原文语域、短片段保持短。
- **术语**：代码标识符与命令名保持原样、品牌名保留原文、同一术语全篇译法一致、相同原文给出相同译文。
- **细节**：数字单位日期按目标语言习惯格式化、使用目标语言标点。

**风格档**（设置页可选，只追加差异部分）：

| 档位 | 用途 |
| --- | --- |
| 自然流畅（默认） | 像母语者写的一样自然 |
| 忠实直译 | 保留原文语序，方便逐句对照学习，代价是中文略生硬 |
| 口语化 | 贴近日常说话，适合对话与字幕 |
| 正式书面 | 正式语域，术语优先 |

**术语表**（设置页填写，每行 `原文=译法`）强制注入每次请求，保证同一术语在全篇译法一致。

**附加要求**（设置页填写）追加在全部规则之后。这是**叠加**而不是替换——内置规则负责格式、术语与防加戏，附加要求只用来补充风格偏好，例如「统一用"您"称呼读者」。

> 系统提示词是每个请求都会重复发送的稳定前缀，只有内容完全一致才能命中厂商的前缀缓存，因此随批次变化的任何东西都不能写进提示词。

## 设计要点

- **内容脚本必须自包含**：内容脚本不能是 ES module，也不该依赖运行时 chunk，因此每个入口都用 esbuild 打成独立 IIFE，共享代码在各包内重复而非抽公共 chunk。
- **网络请求统一走 Service Worker**：内容脚本的跨域 `fetch` 受页面 CORS 约束且其 IndexedDB 属于页面源，所以翻译请求与缓存全部由 SW 承担。
- **缓存键不含页面信息**：同一句话在不同页面命中同一条缓存；但包含模型、系统提示词、温度与术语表，改提示词即自动失效。
- **Google 接口的返回结构随输入条数变化**：多个 `q` 参数返回扁平字符串数组，单个 `q` 返回嵌套数组，解析器同时兼容两种（见 `tests/google.test.ts` 中记录的真实样例）。
- **提示词协议**：正文用 `<<1>>…%%<<2>>…` 编号分块，解析时优先按标签归位（容忍模型调换顺序），再回退到按分隔符顺序解析。
- **译文插在原段落内部**（`display:block` 的 `<span>`），不作为兄弟节点：兄弟节点会改变父级 flex/grid 布局，插在 `li`/`td` 外层还会破坏列表与表格结构；用 `span` 而非 `div` 是因为 `div` 不能出现在 `<p>` 内部。正文翻译**不用 Shadow DOM**，否则译文无法参与页面查找与选区。
- **注入 UI 的配色跟随页面背景**而非系统偏好：很多站点用固定浅色主题，只跟随系统会导致深色气泡浮在浅色页面上。
- **会话级去重**：段落入队时立刻打标记并记入 `touched` 集合。仅靠 DOM 标记不够——入队到处理之间有一段空档，SPA 重扫会在这段时间里把同一段落再排一次队，导致译文重复。
- **提取正文不能用 `textContent`**：它会把 `<script>`/`<style>` 里的**源码**也算作文本。页面上常见「容器里只装一段脚本」的结构，一旦当成段落处理，整段 JS 会被送去翻译（`function`→函数、`var`→变量），译文再作为可见文本插回页面。改为只遍历文本节点、跳过非正文标签。
- **样式分三层而不是一份**：内嵌 UI 只需要按钮和令牌，扩展页面需要整套组件。如果全部内联进内容脚本，每个网页都要多背一份用不到的组件样式；分开后 content.js 少约 9 KB。
- **不装 Tailwind 与 Radix**：项目用 Preact，引入这些会把构建复杂度与体积一起带进来。手写等价 CSS 的代价是改动时要对照上游，收益是内容脚本里没有任何框架运行时。
